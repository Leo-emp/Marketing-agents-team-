## 3. Scheduling & Auto-Pipeline

### 3.1 Content Strategy: Staggered Cross-Posting

Each original piece of content is adapted and posted across multiple platforms with platform-specific formatting and captions. The pipeline generates N original ideas per week, then auto-adapts each into platform variants (different dimensions, caption tone, hashtags, format).

The specific content calendar — how many originals per week, which platforms each posts to, what days and times — is **configurable from the dashboard**, not hardcoded. The system supports any combination of:
- Content types: single image, carousel (4-6 slides), reel, thread, plain text
- Platforms: LinkedIn, X/Twitter, Instagram, TikTok
- Scheduling: any day/time per post

### 3.2 Sunday Night Auto-Generation Pipeline

New route: `src/app/api/pipeline/weekly/route.ts`

Cron: `0 22 * * 0` (Sunday 10 PM UTC)

Pipeline steps (sequential):
1. **Pull performance digest** — top/bottom 3 posts from last week, platform engagement averages, best content pillars
2. **Read content calendar config** — how many originals, which platforms, what types
3. **Generate weekly plan** — strategist agent creates content plan informed by performance data and calendar config
4. **Generate original content** — platform agents produce text/captions, editorial agent scores and refines
5. **Generate platform variants** — adapt each original to target platforms (reformat dimensions, adjust caption tone, add platform-specific hashtags)
6. **Render all visuals** — OpenAI generates images for singles + carousel slides, pdf-lib assembles carousel PDFs
7. **Render all videos** — Remotion/fal.ai renders reels, ElevenLabs generates voiceovers, captions burned in
8. **Queue everything** — all pieces saved as Content records with status `pending`, linked by `variationGroup`

All content is ready for review by Monday morning.

### 3.3 One Approval Gate

User opens dashboard → sees all pending pieces → approves/rejects each individually.

On approval:
- Status changes to `scheduled`
- `scheduledFor` is auto-set based on the calendar config (day + optimal time slot for that platform)
- No further manual action needed

On rejection:
- Status changes to `rejected`
- Optional: user can add a note explaining why (feeds back into learning)

### 3.4 Scheduler Cron Upgrade

Change scheduler from daily (`0 9 * * *`) to every 30 minutes (`*/30 * * * *`):
- Queries Content with status `scheduled` and `scheduledFor <= now`
- Posts to the target platform via `social-posting.ts`
- Updates status to `posted` with `postedAt` timestamp
- Handles UTM tagging, hashtag injection, platform routing

### 3.5 Failed Post Retry

- On first failure: mark as `failed`, set `retryAt = now + 30 minutes`
- Scheduler picks up `failed` posts with `retryAt <= now` for one retry
- On second failure: stays `failed` for manual intervention
- Common failures: expired tokens (prompt re-auth), rate limits (wait), API errors (log)

## 4. Text Quality & Engagement Feedback Loop

### 4.1 Auto-Pull Engagement from Platform APIs

New route: `src/app/api/engagement/pull/route.ts`

Cron: `0 8 * * *` (daily 8 AM UTC)

For each Content with status `posted` in the last 7 days, pull metrics from the platform API:

| Platform | API | Metrics |
|---|---|---|
| LinkedIn | UGC Posts API | likes, comments, shares, impressions |
| X/Twitter | Tweet Metrics v2 | likes, retweets, replies, impressions |
| Instagram | Graph API insights | likes, comments, saves, reach, impressions |
| TikTok | Content Stats API | views, likes, comments, shares |

Updates the Content record's engagement fields and recomputes the composite score using the existing weighted formula: saves×5, shares×4, comments×3, likes×1, impressions×0.01.

### 4.2 Dynamic Voice Samples

Replace static `voice-samples.ts` with a dynamic system:

Before generating content for a platform + content type:
1. Query top 3 performers for that platform + type from the last 30 days
2. Inject them as few-shot examples into the agent prompt: *"Here are your best-performing posts on LinkedIn recently. Study what made them work. Write content at this quality level or better."*
3. Fall back to static samples when insufficient data (first few weeks)

New file: `src/lib/dynamic-voice.ts`
- `getTopPerformers(platform: string, contentType: string, limit: number): Promise<Content[]>`
- `buildVoiceSamples(platform: string, contentType: string): Promise<string>` — returns formatted few-shot prompt section

### 4.3 Weekly Performance Digest

Injected into the strategist agent's prompt during Sunday night pipeline:

- Top 3 posts of the week (content, platform, type, metrics, engagement score)
- Bottom 3 posts (what didn't work)
- Platform-by-platform average engagement rate
- Best-performing content pillars and frameworks
- Week-over-week trend (improving/declining/stable)

New file: `src/lib/performance-digest.ts`
- `generateWeeklyDigest(): Promise<PerformanceDigest>`
- Returns structured data that's serialized into the strategist prompt

### 4.4 A/B Variation Learning

Close the existing variation loop (`variationGroup` field, `generateVariations()`):

- After 48 hours of engagement data on a variation group, auto-flag the winner
- Feed the winning variation's style/approach into the dynamic voice samples
- The editorial agent gets context: *"Variation A (contrarian hook) outperformed Variation B (stat hook) by 3x on LinkedIn — favor contrarian hooks for similar topics"*

### 4.5 Editorial Agent Enhancement

Upgrade the editorial scoring pass:

**Multi-dimensional scoring** (replace single composite score):
- Hook strength (1-10) — does the first line stop the scroll?
- Specificity (1-10) — concrete details vs. vague platitudes
- Brand alignment (1-10) — does this sound like our high-performers?
- Platform fit (1-10) — right length, tone, format for the platform?

**Performance-informed editing:**
- Inject top-performers data so the editor knows what voice/style resonates
- Add brand consistency check — does this match our established voice?
- Reject content scoring below 7/10 on any dimension — regenerate with feedback

## 5. Content Strategy Summary

### 5.1 Staggered Cross-Posting Model

Each original piece is adapted across platforms with staggered timing for maximum reach:
- **Original** posts first on its primary platform
- **Variants** post to other platforms 1-2 days later with platform-native formatting
- Staggering gives daily presence across all platforms and allows performance-informed tweaks before cross-posting

The specific calendar (which days, platforms, content types, volume) is **dashboard-configurable** — not hardcoded. The system supports any mix of content types (single image, carousel, reel, thread, text) across any platforms (LinkedIn, X/Twitter, Instagram, TikTok).

Plus 2 ambassador videos/week (Tue/Thu, existing pipeline).

### 5.2 Content Type → Rendering Engine

| Content type | Engine | Format |
|---|---|---|
| Single image | OpenAI gpt-image-1 | PNG (platform-specific dimensions) |
| Carousel | OpenAI gpt-image-1 → pdf-lib | PDF for LinkedIn, PNG set for others |

| Cinematic reel | fal.ai + ElevenLabs VO | MP4 1080×1920 |
| Ambassador video | HeyGen + caption burner | MP4 1080×1920 |
| Thread / plain text | Gemini text generation | Text only |
